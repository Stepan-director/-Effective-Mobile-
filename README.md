# Анализ и проектирование корзины (Petrushka Green)

В этом документе представлены результаты анализа требований к функционалу корзины, исправленный ТЗ, пример API для получения магазинов доставки.

---

## Задание 1: Анализ требований

### Исходные требования (ТЗ)

Функционал корзины согласно первоначальной версии:

1. Пользователь может добавить в корзину от 1 до 10 единиц одного товара.
2. Пользователь может изменить количество каждого товара в корзине не менее, чем до 1-го. Для удаления товара из корзины используется отдельная кнопка.
3. В корзине может находиться не более 5 различных товаров.
4. Суммарное количество всех товаров в корзине не может превышать 20 штук.
5. Товары в корзине могут быть разные.
6. При попытке добавить товар, превышающий лимиты, система показывает сообщение: "Лимит корзины превышен".
7. Цена на продукт фиксируется на момент добавления в корзину и не меняется.
8. На странице корзины отображается список товаров, их количество, цена за единицу и общая стоимость позиции.
9. Если пользователь уменьшает количество товара до 0, товар удаляется из корзины.
10. В корзине может быть реклама других продуктов.
11. Реклама товаров в корзине должна быть каждый будний день по утрам и вечерам.
13. Если цена на товар изменилась в каталоге, система должна автоматически обновить ее в корзине у всех пользователей.

---

### 1.1 Противоречия и недочёты

| Пункт | Проблема |
|-------|----------|
| 2, 9 | Пункт 2 говорит: "для удаления товара используется отдельная кнопка". Пункт 9: "если пользователь уменьшает количество до 0, товар удаляется". Противоречие: два разных способа удаления. |
| 1, 4, 6, 3 | Пункт 1: макс. 10 ед. одного товара. Пункт 4: суммарно не более 20 штук. Пункт 3: не более 5 разных товаров. При нарушении лимитов сообщение "Лимит корзины превышен" — неконкретное. |
| 3, 4 | Одновременное ограничение "<=5 разных товаров" и "<=20 штук всего" — неясна бизнес-логика двух независимых лимитов. |
| 7, 13 | Прямое противоречие: п.7 — цена фиксируется при добавлении и не меняется; п.13 — цена должна автоматически обновляться из каталога. |
| 8, 10 | Неясно, учитывается ли реклама в отображении списка товаров. |
| - | Отсутствие описания ошибок. |

### 1.2 Исправленная версия ТЗ

1. Пользователь может добавить от 1 до 10 единиц одного товара. При попытке добавить больше 10 единиц одного товара — сообщение: "Нельзя добавить более 10 единиц одного товара".

2. Удаление товара из корзины производится кнопкой "Удалить". Изменение количества товара возможно от 1 до 10 единиц. Уменьшение количества до 0 не удаляет товар — для удаления используется специальная кнопка.

3. В корзине может находиться не более 5 различных товаров. При попытке добавить 6-й уникальный товар — сообщение: "В корзине может быть не более 5 разных товаров".

4. Суммарное количество всех товаров в корзине не может превышать 20 штук. При попытке добавления, нарушающей этот лимит — сообщение: "Общее количество товаров в корзине не может превышать 20 штук".

5. Цена товара фиксируется в момент добавления в корзину и далее не меняется, даже если цена в каталоге изменилась. (Пункт 13 удалён как противоречащий п.7).

6. На странице корзины отображается список добавленных товаров (без учёта рекламных блоков) с полями: название, количество, цена за единицу (на момент добавления), общая стоимость позиции.

7. Реклама других товаров отображается отдельным блоком вне списка товаров корзины (например, сверху или снизу). Реклама не влияет на лимиты по количеству товаров и не сохраняется как часть корзины.

8. Реклама показывается согласно отдельному маркетинговому расписанию (не в рамках логики корзины). В данном ТЗ описание расписания рекламы выносится в отдельный раздел.

### 1.3 Вопросы продукт-менеджеру / заказчику

2. Приоритет лимитов: какой лимит проверять первым при добавлении товара? Если текущая корзина: 5 разных товаров, 19 шт, пользователь пытается добавить 2 шт существующего товара — что важнее: превышение суммарного лимита (станет 21) или лимит на 1 товар (если добавить 2 шт к уже 9 шт того же — станет 11)? Или показывать первое сработавшее ограничение?

3. Цена: окончательное решение — фиксировать при добавлении или обновлять динамически из каталога? (Пункты 7 и 13 взаимоисключающие. Нужен выбор бизнеса.)

4. Реклама: как технически понимать "по утрам и вечерам" в каждый будний день? Какие часы считаются утром и вечером? Зависит от часового пояса пользователя или сервера?

5. Удаление при уменьшении до 0: хотите ли вы вообще поддерживать такой способ удаления, или оставить только кнопку "Удалить"? Рекомендую оставить только кнопку "Удалить", а счётчик количества ограничить диапазоном 1–10.

6. Сообщения об ошибках: нужны ли разные сообщения для каждого типа превышения лимита, или одно общее "Лимит корзины превышен" допустимо?

## Задание 2: Проектирование API

### Запрос

GET /api/v1/delivery-stores?lat=55.751244&lon=37.618423&radius=15&limit=50
Host: api.petrushka-green.ru
Authorization: Bearer <токен_пользователя>
Accept: application/json

### Параметры запроса

| Параметр | Тип | Обязательный | Описание | По умолчанию |
|----------|-----|--------------|----------|--------------|
| lat | float | Да | Широта пользователя | - |
| lon | float | Да | Долгота пользователя | - |
| radius | int | Нет | Радиус поиска в км | 10 |
| limit | int | Нет | Максимум магазинов в ответе | 20 |
